# Silent camera scans — preview only

The phone test uses two short, silent camera scans. Before each scan, a large animated diagram shows the movement: keep the phone in front at forehead height and bow forward/back for the hairline, top and crown; then turn right and left for the two profiles. Each scan has a three-second preparation countdown and eight-second capture window. There is no speech, sound playback, microphone request or MediaRecorder. The camera feed supplies still images; no video file is recorded or uploaded.

The patient agrees to camera images being checked by Anthropic AI and five accepted photographs being saved privately. Up to twelve candidate instants per scan are held temporarily in browser memory. Each instant produces a 640px JPEG for selection and a JPEG up to 1536px for the final photo. Local brightness/blur checks reject poor candidates. The server uses the existing configured Anthropic model to select only genuinely visible, clear requested angles; missing or uncertain regions are omitted. Its strictly parsed response cannot reuse a frame or a view, invent a frame index, or choose an unrequested view. The selected full-resolution images are checked independently again before private storage. Only the five accepted images enter the final Norwood assessment together.

Already accepted photos survive a partial scan. The next attempt requests only missing angles and displays a focused diagram if one is missing. A face-only image cannot stand in for the top or crown. The crown requires the upper back of the scalp and surrounding anatomy; bald scalp does not require a visible whorl. Opposite side profiles must be genuinely opposite. Frame selection is fallible and is not evidence of measured clinical grading accuracy.

The server enforces the existing hashed two-hour link, camera-frame consent, completed-view checks, at least three seconds between selection requests and 120 framing/selection requests per link. Each selection request has at most twelve 640px JPEGs, each limited to 150,000 decoded bytes. Images are transient in the application/provider request and are not stored by this selection endpoint. The existing separate limits on uploads and final analysis remain. The server never returns patient records through the link. Private photo access, rep confirmation, the 6–7 expectations gate, separate AI/final audit records and clinic handover remain unchanged.

A stopped or hidden scan cancels its timer and releases the camera. Stale camera responses cannot resume it. Hidden/unmounted scans discard pending candidates; frames already sent to the server may finish processing. A session revision prevents older status polls from overwriting newly accepted photos. On camera-access failure, the patient can use the phone-camera file fallback; files are re-encoded without EXIF before transmission.

The design fits ordinary portrait phone viewports without scrolling; enlarged accessibility text may scroll rather than clip. There is no patient login and no preview label in the patient page. Camera permission is still required by the browser. The hosting URL remains the existing shared Lovable test URL. Production is not published.

Verification uses synthetic camera frames and mocked server selection to exercise two-scan completion, missing-angle retry and cancellation without patient photos or messages. Automated tests cover strict selection, provider failures and the existing assessment/privacy/SMS contracts. Real-device testing during a live call remains necessary, especially whether bowing exposes enough of the crown and whether the mobile browser retains camera access during the call. This release does not establish a clinical accuracy percentage.

The SMS remains exactly: `Hi [NAME] please see link below for our ai norwood scale scanner [link]`.

## 16 October: simpler screen and response-retry fix

The reported message “We couldn’t find clear angles in that scan” came from the selection-response parsing/validation catch, not from a successful assessment that found no usable angles. The prior code returned an empty selection normally. Without the transient provider response, the exact invalid field or syntax cannot be reconstructed, and this report does not establish whether the patient's original angles were sufficient.

Selection and per-photo checks now request Anthropic JSON-schema outputs. The server still checks valid frame indices, unique views/frames and requested anatomy. It retries one unreadable/incomplete selection response with the same still images and a validation reminder, within one 40-second request budget. Provider failures/refusals do not become valid photographs or automatic retry loops. A valid empty selection remains a request to capture the missing angle. The browser retains candidates in memory after the explicit technical selection error, so the large Retry button checks those same images instead of forcing another movement. It drops those candidates on hide, stop, unmount, a stage change or successful processing. No photo contents, patient tokens or raw model output are logged.

The patient capture screen now shows one action, one brief phone-position hint and the existing animated guide. Repeated instructions and the sound/video footer copy were removed. A failed or partial attempt shows a 60–64px-high Retry button. The intro has a restrained decorative hairline photo; “No account needed · About 2 minutes” and “No photos go to the clinic” were removed as requested. This changes copy only: clinic handover still excludes photos.

Reference: [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), checked 16 October 2026. The configured default Haiku 4.5 supports JSON-schema output. Unsupported numeric/array constraints are kept in local validation rather than the provider schema. Structured formatting does not validate the medical or anatomical correctness of an answer.
