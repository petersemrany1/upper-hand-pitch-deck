# Silent camera scans — preview only

The phone test uses two short, silent camera scans. Before each scan, a large animated diagram shows the movement: keep the phone in front at forehead height and bow forward/back for the hairline, top and crown; then turn right and left for the two profiles. Each scan has a three-second preparation countdown and eight-second capture window. There is no speech, sound playback, microphone request or MediaRecorder. The camera feed supplies still images; no video file is recorded or uploaded.

The patient agrees to camera images being checked by Anthropic AI and five accepted photographs being saved privately. Up to twelve candidate instants per scan are held temporarily in browser memory. Each instant produces a 640px JPEG for selection and a JPEG up to 1536px for the final photo. Local brightness/blur checks reject poor candidates. The server uses the existing configured Anthropic model to select only genuinely visible, clear requested angles; missing or uncertain regions are omitted. Its strictly parsed response cannot reuse a frame or a view, invent a frame index, or choose an unrequested view. The selected full-resolution images are checked independently again before private storage. Only the five accepted images enter the final Norwood assessment together.

Already accepted photos survive a partial scan. The next attempt requests only missing angles and displays a focused diagram if one is missing. A face-only image cannot stand in for the top or crown. The crown requires the upper back of the scalp and surrounding anatomy; bald scalp does not require a visible whorl. Opposite side profiles must be genuinely opposite. Frame selection is fallible and is not evidence of measured clinical grading accuracy.

The server enforces the existing hashed two-hour link, camera-frame consent, completed-view checks, at least three seconds between selection requests and 120 framing/selection requests per link. Each selection request has at most twelve 640px JPEGs, each limited to 150,000 decoded bytes. Images are transient in the application/provider request and are not stored by this selection endpoint. The existing separate limits on uploads and final analysis remain. The server never returns patient records through the link. Private photo access, rep confirmation, the 6–7 expectations gate, separate AI/final audit records and clinic handover remain unchanged.

A stopped or hidden scan cancels its timer and releases the camera. Stale camera responses cannot resume it. Hidden/unmounted scans discard pending candidates; frames already sent to the server may finish processing. A session revision prevents older status polls from overwriting newly accepted photos. On camera-access failure, the patient can use the phone-camera file fallback; files are re-encoded without EXIF before transmission.

The design fits ordinary portrait phone viewports without scrolling; enlarged accessibility text may scroll rather than clip. There is no patient login and no preview label in the patient page. Camera permission is still required by the browser. The hosting URL remains the existing shared Lovable test URL. Production is not published.

Verification uses synthetic camera frames and mocked server selection to exercise two-scan completion, missing-angle retry and cancellation without patient photos or messages. Automated tests cover strict selection, provider failures and the existing assessment/privacy/SMS contracts. Real-device testing during a live call remains necessary, especially whether bowing exposes enough of the crown and whether the mobile browser retains camera access during the call. This release does not establish a clinical accuracy percentage.

The SMS remains exactly: `Hi [NAME] please see link below for our ai norwood scale scanner [link]`.

## 16 October: simpler screen and response-retry fix

The reported message “We couldn’t find clear angles in that scan” came from the selection-response parsing/validation catch, not from a successful assessment that found no usable angles. The prior code returned an empty selection normally. Without the transient provider response, the exact invalid field or syntax cannot be reconstructed, and this report does not establish whether the patient's original angles were sufficient.

Selection and per-photo checks now request Anthropic JSON-schema outputs. The server still checks valid frame indices, unique views/frames and requested anatomy. It retries one unreadable/incomplete selection response with the same still images and a validation reminder, within one 40-second request budget. Provider failures/refusals do not become valid photographs or automatic retry loops. A valid empty selection remains a request to capture the missing angle. The browser retains candidates in memory after the explicit technical selection error, so the large Retry button checks those same images instead of forcing another movement. It drops those candidates on hide, stop, unmount, a stage change or successful processing. No photo contents, patient tokens or raw model output are logged.

The patient capture screen now shows one action, one brief phone-position hint and the existing animated guide. Repeated instructions and the sound/video footer copy were removed. The intro has a restrained decorative hairline photo; “No account needed · About 2 minutes” and “No photos go to the clinic” were removed as requested. ## 16 October: Hair Profile and one-position capture

The patient-facing name is **Hair Profile**, with a smaller **AI-assisted assessment** label. Sans-serif type, dark evergreen, warm ivory and restrained brass details replace the oversized default serif title. The SMS text remains exactly as requested. No protected sales portal or unrelated page is changed.

The public phone-test route now uses `NorwoodGuidedCapture`. The previous eight-second sweep tried to get three upper-head views in one movement, then selected small frames and independently checked selected originals. It provided no correction until the sweep ended. The new flow asks for one still position at a time, shows both phone placement and the region needed, waits 6 seconds (8 for top/crown), captures automatically, and gives a specific correction when framing fails. A corrected view is rechecked automatically; after four misses the camera pauses with Retry and a native Phone camera option. Patients can also pause and switch cameras. Everything remains silent, with `audio: false`.

`capturePatientNorwoodFrame` validates consent/expiry/view/quota, checks one full-resolution still and saves exactly those bytes if the check passes. There is no second AI gate and no generic local blur rejection for a smooth bald scalp. This is not acceptance of blurry photos: the server still checks blur, light, head presence and the requested anatomy. Missing/wrong views do not advance. Each accepted image remains saved when another angle needs work. Final grading still requires all five distinct images and the existing evidence rubric. No relaxed grading or claimed accuracy percentage.

Technical failures keep only the current still in browser memory for Retry. Hiding/leaving pauses the camera and clears that retained image. Saved progress remains in the existing private bucket. Provider handling has a bounded second attempt and a forced-tool compatibility fallback only if the API explicitly rejects structured-output configuration. Local validation still applies. Diagnostics log only a fixed code, model and provider request ID, never images, raw responses or patient tokens.

Before enabling the test SMS button, the existing authenticated readiness check now sends a generated 64px grey square through the real image-check API. This verifies credentials, model access, image handling and response parsing without using a patient's photo. A successful check is cached for five minutes. It does not establish clinical accuracy.

## 16 October: supported-phone movement capture

The opening page is unchanged. Capture now starts with a large, silent setup illustration: rest the phone at eye level, screen facing the seated patient. The five guides keep the phone supported and move the head/body instead of asking the patient to aim it overhead. Top uses a forward head tilt; crown adds a comfortable forward lean. Start this photo opens the camera and begins sampling after frames are ready. The patient copies the movement and taps Done; there is no separate Open camera / Start pair. The back control returns to the large demonstration for this angle. This is a proposed ergonomic improvement, not a validated guarantee that every person can expose the crown independently.

Start begins a silent sequence of stills. Done stops it after the patient returns to the screen; there is no single shutter countdown to catch. Capture is bounded at 28 seconds and eight retained originals. Sampling uses a tiny brightness-normalised thumbnail locally to retain visually different positions, with time spacing as a tie-breaker. A briefly bowed head is therefore not automatically discarded when the patient takes longer to look up and press Done. This is image diversity sampling, not head/pose detection; anatomy is still checked on the server. The server checks each candidate and saves exactly one accepted original per requested angle, using the existing anatomical criteria. No quality or final assessment gate has been weakened. The eight candidates are checked in at most three concurrent requests, each containing at most three originals. Each selected frame has passed the unchanged anatomical gate; valid choices closer to the middle of the movement are preferred. An eight-image live fixture had rejected the frontal image that the smaller request accepted, so the crowded request was not retained. Provider reply capacity covers each small group. The readiness probe verifies selection of frame 6 in an eight-image fixture and rejection of a frontal fixture as crown. These generated fixtures test plumbing/basic framing, not diagnostic accuracy.

A rejected attempt can display the exact locally retained frame used for its correction. That image is not newly uploaded for display and does not enter storage. The patient can toggle the large movement guide and retry just this angle. Hidden-page/unmount handling clears retained capture/review images, stops camera tracks and prevents late results from restoring the image. Already-submitted requests can finish on the server. Technical retries reuse the exact original candidates. The microphone remains unrequested.

Route-specific Hair Profile social tags override portal tags on the direct patient route. The existing SMS still enters through a Lovable guest-sharing wrapper; these route tags alone do not establish that iMessage will change the wrapper's project-level card. No global portal title/image or production publishing settings were changed.
